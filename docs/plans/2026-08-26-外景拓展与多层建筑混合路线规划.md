## 0. 现状架构勘察（2026-08-26 代码核实）

为什么现在是"单层平房"——整套引擎是单层 2.5D 符号地图模型，各系统逐项核实如下：

| 系统 | 现状 | 对多层的影响 |
| --- | --- | --- |
| 数据 | `LevelData` 符号图，一格一状态（与 C++ 同源，不可手改） | 无法表达"房间上方再有房间"（DOOM 时代的经典限制），数据模型是根源 |
| 几何 | 墙=2.6m 盒（`WorldConst.WALL_HEIGHT`），地板/天花板=整片 PlaneMesh 矩形 | 墙盒可叠高，但楼板必须从整片矩形改"逐格板 + 挖洞" |
| 碰撞 | 单个 StaticBody3D 每墙格一个共享 BoxShape3D + WorldBoundaryShape3D 无限地面 | 多层需追加逐格楼板形状，数量翻 2-3 倍，可能需条带合并优化 |
| 玩家 | CharacterBody3D，重力，move_and_slide（默认 ≤45° 坡可行），**无跳跃键** | 层高通行必须靠坡道/踏步吸附，属 P2b 范畴；台阶式楼梯直接爬不上 |
| 敌人 | CharacterBody3D，侦测/攻击距离=水平投影（**完全忽略 y**），纯水平面转向 | 多层后会隔层误侦测、对楼板开火；自己不会走楼梯 |
| 子弹 | 3D 物理飞行，命中静态体即止 | 楼板有碰撞即天然遮挡，零改动 |
| 小地图 | wall_cells 俯视投影 | 多层重叠歧义，需引入"当前楼层"概念 |

结论：**可玩多层是数据模型升级，不是几何堆叠**；但**三层外观可以用装饰外立面廉价兑现**。
两个目标成本相差一个数量级 → 混合路线分阶段执行。

## 阶段一（立即可做，不依赖 P2b）：外立面布景 + 庭院道具

目标：穿门回头见三层仓库体量，庭院道具丰富场景。**零玩法逻辑改动**——
外立面与道具均不进 `wall_cells`/buckets，碰撞、敌人 AI、子弹、小地图全部零改动。

### 1.1 外立面（Facade）

**形态决策**：一层保留现有砖墙与门洞视觉（零风险），外立面面板自现有墙顶之上起
（y: 2.6m → 7.8m，即二/三层），顶部收一条女儿墙/屋檐。总高 ≈ 3 × WALL_HEIGHT ≈ 7.8m。

**空间锚点**：挂庭院西缘（map0 col 167 原东边界列，rows 26-38），面板贴原墙东面
（庭院一侧）竖立；可沿南北向越过庭院范围多延伸 1-2 格，增强建筑完整感（具体范围实机调）。

**配置 schema**（`level_ext.json` 新增 `"facade"` 段）：

```json
"facade": {
  "map": 0,
  "col": 167, "rowMin": 26, "rowMax": 38,
  "stories": 2, "storyHeight": 2.6,
  "wallTexture": "res://assets/images/Facade Panel.bmp",
  "windowTexture": "res://assets/images/Facade Windows.bmp",
  "parapet": true
}
```

**生成逻辑**：`LevelGenerator.gd` 新增 `_build_facade()`，MultiMesh/PlaneMesh 拼
层带 + 女儿墙（UNSHADED，与全图一致）；节点挂 Level 子树但**不登记 wall_cells、
不生成碰撞**——玩家本就到不了庭院西缘之外，原边界墙碰撞已在。

**新贴图需求**（AI 生成 + 用户确认，硬边像素风对齐现有墙材质）：

1. `Facade Panel.bmp` — 仓库外墙板材（金属/混凝土，延续 S/M 贴图语言）
2. `Facade Windows.bmp` — 窗户带（多数暗窗 + 零星亮窗；全 UNSHADED 无光影，
   唯有亮窗能撑出体积感，这是观感关键）

**验收点**：①庭院回头可见清晰三层体量、窗户带可辨；②与原墙/庭院围墙/天花板边缘
无 z-fighting；③夜空雾参数（0.0045）下不糊；④玩法回归 77/77 不变。

### 1.2 庭院道具（Props）

**配置 schema**（`level_ext.json` 新增 `"props"` 数组）：

```json
"props": [
  { "map": 0, "sprite": "res://assets/sprites/Prop Rubble.png", "x": 172, "y": 29, "scale": 1.0 }
]
```

**生成逻辑**：`LevelGenerator.gd` 新增 `_spawn_props()`，复用 Sprite3D billboard
技术（敌人/拾取物同源）；**首批不加碰撞**（可穿过，避免干扰 AI 与寻路），
大件道具后续视观感再补碰撞。

**首批候选**（3-5 种，sprite AI 生成，高清源进 `assets-src/`）：
瓦砾堆、木箱、路灯或火桶、枯树。

**验收点**：道具按配置落位、billboard 朝向正确、玩法回归不变。

### 1.3 阶段一文件清单（预计）

1. 🆕 `godot/assets/images/Facade Panel.bmp` + `Facade Windows.bmp`（外立面贴图）
2. 🆕 `godot/assets/sprites/Prop *.png`（首批道具精灵）
3. `godot/assets/config/level_ext.json`（加 facade + props 段）
4. `godot/scripts/levels/LevelGenerator.gd`（`_build_facade` + `_spawn_props`）
5. `godot/scripts/tests/SmokeTest.gd`（新增断言：外立面节点存在且高度达标、道具数量
   与配置一致、**逻辑零侵入不变式——墙碰撞体子节点数 == 墙格数，证明布景未混入逻辑层**）
6. `STATUS.md` 同步

**风险**：外立面贴图风格、雾与立面的作用、门洞框景遮挡关系均需实机微调
（P2a 前例：雾参数即实机调定项）。

## 阶段二（P2b 之后）：可玩二层夹层 + 层叠数据模型

**前置**：P2b 斜坡/楼梯与地面吸附落地（玩家层间通行；敌人地面吸附是跨层 AI 的前提）。

### 2.1 层叠数据模型（layers）

`level_ext.json` 新增 `"layers"` 段：每层一张独立符号网格（沿用现有符号语义），
上层网格为下层的**子集**（用户明确要求二/三楼比一楼小，立面自然退台）：

```json
"layers": [
  {
    "map": 0, "floor": 2,
    "rect": { "x": 150, "y": 26, "w": 18, "h": 13 },
    "grid": "XXXXXXXX\nX  H   X\n...",
    "slabHoles": [ { "x": 166, "y": 32 } ]
  }
]
```

首期范围：**东侧仓库上方一小块二层夹层**（约一楼面积的 1/4-1/3），坡道/楼梯连通上下，
正好压在门洞回头视线里——回头看到真建筑，抬头有可玩楼层。

### 2.2 系统改动清单

| 系统 | 改动 | 风险 |
| --- | --- | --- |
| 渲染 | MultiMesh 墙盒按层 y 偏移，现有技术 | 无 |
| 楼板 | 整片 PlaneMesh → 逐格板，楼梯/挑空挖洞 | 中（几何主要工作量） |
| 碰撞 | 追加逐格楼板形状；数量翻 2-3 倍，必要时条带合并优化 | 中 |
| 玩家 | 依赖 P2b 坡道/楼梯；重力已备 | 依赖 P2b |
| 敌人 AI | 侦测加垂直差阈值 + 视线楼板遮挡（禁止隔层侦测）；首期设计上约束：二层少刷/不刷敌 | 高（需 P2b 地面吸附） |
| 子弹 | 3D 飞行，楼板有碰撞即天然遮挡 | 无 |
| 小地图 | 引入"当前楼层"，按玩家所在层取墙集 | 中 |
| SmokeTest | 新增断言：坡道上下通行、楼板遮挡视线、小地图楼层切换、敌人不跨层侦测 | — |

### 2.3 范围克制

阶段二只做一块可玩二层夹层；三层留给阶段三装饰件；敌人跨层 AI 完整版
（层感知寻路）不在阶段二范围内。
