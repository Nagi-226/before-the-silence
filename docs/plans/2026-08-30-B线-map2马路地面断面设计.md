## 一、街道断面（垂直于街道方向）

```
北 → 南（东西向主街，总宽 6 格 = 12m）
┌─────────────┬───────────────┬───────────────┬───────────────┬───────────────┬─────────────┐
│ 建筑墙/装饰体块 │ 人行道 1 格      │ 沥青马路 4 格（8m 车道）                    │ 人行道 1 格      │ 建筑墙/装饰体块 │
│             │ Floor Tile     │ EdgeN│CenterN│CenterS│EdgeS │ Floor Tile     │             │
│             │ （材质不变）     │ 白实线│黄虚线½│黄虚线½│白实线 │ （材质不变）     │             │
└─────────────┴───────────────┴───────────────┴───────────────┴───────────────┴─────────────┘
                                    └── 接缝合成完整黄虚线 ──┘
```

- **马路**：4 格沥青，交通线 = 中心黄虚线（做旧）+ 两侧白实线（路牙分界）
- **人行道**：马路两侧各 1 格，**沿用现有 `Floor Tile.bmp` 材质不变**（用户明确）
- **再往边**：建筑物墙面（B 批 2 的 B1-B3 可进入建筑 / 南侧装饰立面体块群）
- 南北向次街同理，使用竖版贴图（线沿 y 走向）；路口/巷口用纯沥青

## 三、机制提案：groundZones 分区地面覆层（CodeBuddy 实施）

现状：`_build_floor_ceiling` 整片 PlaneMesh 单材质（Floor Tile）；P2a 庭院已有**覆层先例**
（覆盖矩形 + 抬升 1cm 防共面）。马路地面沿用同一思路，配置驱动：

```json
"maps": [{
  "map": 2, "width": 140, "height": 84, "...": "...",
  "groundZones": [
    { "rect": { "x": 2, "y": 40, "w": 120, "h": 1 }, "texture": "res://assets/images/Road Asphalt EdgeN.bmp" },
    { "rect": { "x": 2, "y": 41, "w": 120, "h": 1 }, "texture": "res://assets/images/Road Asphalt CenterN.bmp" },
    { "rect": { "x": 2, "y": 42, "w": 120, "h": 1 }, "texture": "res://assets/images/Road Asphalt CenterS.bmp" },
    { "rect": { "x": 2, "y": 43, "w": 120, "h": 1 }, "texture": "res://assets/images/Road Asphalt EdgeS.bmp" }
  ]
}]
```

- **逐行 zone**（h=1，w=街长）即可实现逐行不同贴图；zone 内 `uv1_scale = (w, h)` 按格平铺
- 每个 zone 一个覆层 PlaneMesh，抬升 `0.01 + 序号×0.002`（防 zone 间共面闪烁；庭院覆层同法）
- 无 groundZones → 回退现状（整片 Floor Tile），**向后兼容零变化**
- **零逻辑侵入**：纯视觉覆层，不进 wall_cells/buckets/碰撞/AI/小地图（不变式断言守护）
- 坐标落位遵守读图坑纪律：zone 矩形按符号 row 口径，实施前对照 B 批 2 街道布局核验

## 五、验收点（实机）

- 主街：沥青马路居中、黄虚线连续无断相、两侧白实线贴路牙、外侧石板人行道与建筑墙层次清晰
- 次街/巷口贴图方向正确（竖线不横躺）、路口无错线
- 夜空环境下沥青明度与雾搭配观感（过暗可调 ASPHALT 基色重跑脚本）
