## 一、目标

1. **转关贯通**：第一关（map0 城区仓库区）通关 → 弹出结算菜单展示战绩 → 用户确认后进入
   第二关（map2 室外街道）。
2. **map2 成形**：室外街道/建筑/多地形关——街区骨架、可进入建筑与装饰建筑、阶梯式废墟
   地形、高点信标（整关节奏"穿楼 → 出街 → 越野"）。
3. **里程碑判据（B-M3）**：第二关可从头打通——从转关落地到 map2 撤离信标全程可玩。

## 二、关键架构决策（三个，均需用户拍板，本文档给默认提案）

### 2.1 map2 数据来源：level_ext.maps 配置段（推荐，红线合规）

**红线**：`LevelData.gd` 自动生成禁手改、与 C++ 归档版同源。map2 新增数据的两条路：

| 方案 | 说明 | 判定 |
| --- | --- | --- |
| **i（默认）**：`level_ext.json` 新增 `maps` 段 | map2 的 `width/height/grid/spawn/flag` 全部走配置层；`LevelGenerator.build` 开头查 `level_ext.maps[map_index]`，命中则用之（含尺寸元数据），否则回退 `LevelData.MAPS`。**LevelData.gd 与 gen 脚本零触碰** | ✅ 推荐：配置层一贯性（P2a 庭院/贴花/地形先例），冲突面小 |
| ii：扩 `tools/gen_level_data.py` 加 map2 源重新生成 | 走生成器"合规"，但改 LevelData.gd 内容，破坏"与 C++ 归档同源"语义；且 C++ 版无 map2，同源性就此断裂 | ❌ 不推荐 |

**连带改动**（方案 i 下）：`LevelData.WIDTH/HEIGHT` 常量被 map0/map1 硬绑定——地板/天花板
PlaneMesh、MiniMap 尺寸等消费点改为"当前地图元数据"（level_ext 命中时取其 width/height，
否则 LevelData 常量）。墙格字典制（`wall_cells`）本就不依赖固定矩形，尺寸无障碍（T4 规划
既有结论）。

### 2.2 关卡序列与 map1 去向：campaign 流程配置 + map1 顺延第三关（默认提案）

**现状勘察**：`Main.gd` 的 `map_index := 0` 且无任何赋值路径——**map1（地下隐匿设施）当前
游戏内不可达**（无选关/无转关），"双地图可通关"仅数据层成立。转关流程正好补此缺口。

`level_ext.json` 新增 campaign 段：

```json
"campaign": { "sequence": [0, 2, 1] }
```

- map_index 保持"数据索引"语义（0/1/2），流程推进按 sequence 游标。narrative 的
  briefings/victory 数组按下标对应（map2 = briefings[2]，需补位）。
- **默认提案**：序列 = **[map0 仓库区 → map2 街道 → map1 地下设施]**。叙事完美闭环：
  提灯先查地上仓库（发现包装转运痕迹）→ 穿越被寄生体占据的城区街道（追踪转运链）→
  深入地下隐匿设施核心（narrative.json 既有第二关简报"仓库地下，藏着一处未见于任何图纸的
  设施——AE-219 孢子的包装与转运痕迹在此汇聚"**正好是终点关文案**，零浪费）。
- 备选：map1 延后/弃用（若用户想让本阶段只做两关，sequence 暂为 [0, 2]，map1 留待后续）。

### 2.3 跨关数据保留策略：全保留（默认提案）

| 项 | 默认提案 | 备选（软重置） |
| --- | --- | --- |
| 已持有武器（冲锋枪/霰弹枪） | ✅ 保留 | ✅ 保留 |
| 武器升级组件等级 | ✅ 保留 | ✅ 保留 |
| 弹匣 | 转关自动补满 | 重置为半满 |
| 备弹/12号霰弹 | ✅ 保留 | 重置为初始值 |
| 生命/防护能量 | ✅ 保留 | 生命重置满、能量清零 |
| 金币 | ✅ 保留 | 保留 |

默认全保留的理由：提灯是**连续行动**（一夜之间的三个阶段），装备延续叙事自然；且第一关
收集的弹药本就是为后续战斗准备的。map2 内按保留状态配置敌人密度与补给（实施批细调平衡）。

## 三、跨关卡结算/转关流程设计（本线批 1 核心机制）

### 3.1 第一关通关触发形态：终点旗移至庭院（默认提案，goals 配置化）

现状：map0 终点旗 = LevelData `F` 符号（室内撤离信标）。用户口径"走到庭院即第一关结束"——

- `level_ext.json` 新增 `goals` 段：`{ "map": 0, "suppressDataFlag": true, "flags": [{ "x": 179, "y": 32 }] }`
  （旗落庭院中部；坐标实施前按 wall_cells 核验，遵守读图偏移坑）。
- `LevelGenerator`：goals 命中时跳过 `F` 符号旗生成、按 flags 配置实例化 GoalFlag（机制与
  现有 F 完全同源）；无 goals 配置回退现状（向后兼容，109 项零破坏）。
- narrative 同步：briefings[0] 结尾与 area_hints 信标指向改"庭院撤离点"口径（文案微调，
  单点维护在 narrative.json）。

### 3.2 状态机与结算 UI

`Main.gd` 现状态机 `briefing / play / ended` 扩展：

```
goal_reached → 若 campaign 游标有下一关:
    state = "level_end"（关卡间结算）:
    - get_tree().paused = true（沿用暂停体系，游戏实体挂 Viewport PAUSABLE 不变）
    - HUD.show_end 扩展: 胜利 + 有下一关时显示「进入下一关 ▸」主按钮
      （键盘 Enter 确认 + 鼠标点击，与现有 R 重打 / ESC 回菜单并存）
    - 战绩口径（见 3.4）
  确认后 → _advance_level()
否则（最终关）: 现有 ended 流程不变（叙事结算 + R/ESC）
```

### 3.3 转关实现：场景内重建（方案 b，保留 Player 实例）

| 步骤 | 说明 |
| --- | --- |
| 1. 清场 | 清空 `entities` 子节点（敌人/拾取物/旗）+ `level` 子节点（几何/碰撞）+ Viewport 内残留弹道 |
| 2. 重建 | campaign 游标 +1 → `level.build(next_map, entities)`（build 内部 self-clear 或新增 rebuild 入口） |
| 3. 玩家 | `global_position = 新 spawn`、`velocity` 清零——**Player 实例保留** → 武器/弹药/升级/生命跨关天然保留（2.3 策略免序列化） |
| 4. 重连 | `_connect_entities()` 重跑（新敌人信号）；hints/小地图/简报按新图重建（`hud.setup_minimap` 重跑） |
| 5. 节奏 | 显示下一关简报（briefing 态）→ 玩家任意键开始（沿用开局流程，转关即"新开局"） |

**方案 b 优势**：免 autoload 序列化/免整场景重载（change_scene 无法带参）；**风险与对策**：
暂停态切换时序（转关全程 paused，dismiss_briefing 时解除，与开局一致）、清场遗漏断言守护
（转关后旧图节点数为零）。

备选方案 a（场景重载 + GameData 存 next_map）：改动更小但 Player 状态需序列化传递，
与"全保留"策略摩擦大——不推荐，文档留档备查。

### 3.4 结算战绩口径（数据来源现状与增量）

现有 `_stats_text()`：击杀 / 拾取 / 用时。用户点名**命中率** → 需增量：

- `Player` 加 `shots_fired` 计数（`_shoot` 内每弹丸 +1？口径：**每次击发 +1**，霰弹一发算一次）。
- `Projectile` 命中敌人时回报（命中计数）：弹丸 `from_player` 且命中敌人 → 玩家 `hits +1`
  （挂 `hit_enemy` 信号或直接计数，实施批定）。
- 结算面板显示：`击杀 X · 命中率 XX% · 拾取 X · 用时 MM:SS`；命中率 = hits / shots_fired。
- **统计粒度**：每关独立（关卡开始时快照，结算显示本关增量）；最终关（map1）通关结算额外
  加一行全程累计（可选，实施批做）。

### 3.5 批 1 断言清单（SmokeTest 只追加）

1. campaign sequence 配置存在且 [0,2,1]；
2. map0 goals 生效：室内 F 旗被抑制、庭院旗存在（`entities` 中 reached 信号节点位置在庭院矩形内）；
3. 传送玩家至庭院旗 → goal_reached → `state == "level_end"`、结算面板可见、进入下一关按钮存在；
4. 确认转关 → `map_index == 2`、map2 几何生成（灰盒围墙/地板格数）、旧图节点清空（`level` 子节点
   中无 Walls_X 残留/实体零残留）；
5. 跨关保留：转关后玩家仍持有第一关拾取的冲锋枪、weapon_tier 不变、弹药口径正确；
6. 命中率计数：射击 N 次（未命中）→ shots_fired == N、命中率 0%；（命中路径复用既有
   "子弹命中敌人"断言扩展）；
7. 无 campaign/goals 配置时回退现状（回归保护，可用配置探针验证分支）。

## 四、map2 布局设计（街道/建筑/地形，本阶段定稿骨架）

### 4.1 尺寸与骨架

**尺寸提案：140×84 格（280m × 168m）**——比方正略宽，呼应"横向穿越城区"节奏；MiniMap
跟随模式（96×54 视窗）天然适配大图。街区骨架（结构示意，非精确格图）：

```
        北 ═════════════════════════════════════════════════
        █ ┌────┐ ┌────┐  次街(南北)  ┌─────┐      ▲F 高点土丘
        █ │B1 转运站│ │B2 便利店│    │B3 派出所│     ▄▄▄▄▄ (东北角)
 出口→  W ═╡  主街（东西向 4 格宽，全图主轴）        ╞═ 巷 ═╗
 (西端) █ └────┘ └────┘              └─────┘          ╔═ 南巷
        █   ┌────┐   ┌────┐ ┌────┐ ┌────┐            ╔═ (南北)
        █   │D1 装饰│  │D2 装饰│ │D3 装饰│ │D4 装饰│  ╔═
        █ ─────────── 南侧沿街带（装饰立面体块群）──────
        南 ═════════════════════════════════════════════════
```

- **主街**：东西向 4 格宽（8m 车道感），贯穿全图——主战场与视觉主轴。
- **次街/南巷**：南北向 2-3 条 2 格宽巷道，街区切分 + 侧翼包抄路线。
- **可进入建筑 ×3**（真几何：墙进 buckets + 内部敌人/拾取）：
  - **B1 转运站**（主街北侧西段，~14×10 格）：叙事核心——AE-219 包装转运痕迹现场，
    内部补给+伏击战；
  - **B2 便利店废墟**（主街北侧中段，~8×6 格）：轻量遭遇战 + 拾取；
  - **B3 派出所废墟**（主街北侧东段，~10×8 格）：重武器补给（霰弹弹药库），中强度敌。
- **装饰建筑体块群**（南侧沿街带 D1-D4 + 零星）：**沿用阶段一外立面经验**——装饰立面/体块
  不进 `wall_cells`/buckets/碰撞/AI/小地图，零逻辑侵入（SmokeTest 不变式守护）；只有南侧
  围合墙（外边界）是真几何。装饰体块用现有 Facade 贴图语言（板材+暗窗）。
- **高点信标**：东北角废墟土丘（阶梯地形，见 4.2），旗在丘顶——整关收束于登高撤离。
- **出生点**：西端主街入口（衔接叙事：从仓库区方向进入街道），身后可加"来路"装饰门洞。

### 4.3 敌人与拾取分布基调（实施批细调）

- 街面：宿主类中坚（匀速扑近适合街道纵向遭遇）+ 孢囊伏击（伪装瓦砾旁贴地）；
- 建筑内部：近战宿主为主（狭窄空间近战压迫）；
- 高点土丘：1 巨型突变体宿主镇守（坡道消耗战，呼应"攻击远比地表个体致命"文案）；
- 拾取：主街推进线稀疏补给，建筑内密（引导探索），土丘顶奖励级补给。

## 七、里程碑与排期

## 八、决策点汇总（请用户拍板）

1. **map1 去向**：默认顺延第三关（sequence [0,2,1]，叙事闭环、资产零浪费）；备选本阶段
   两关制（[0,2]，map1 后续再排）。
2. **跨关保留**：默认全保留 + 弹匣自动补满；备选软重置（§2.3 表）。
3. **第一关终点**：默认旗挪庭院（goals 配置化 + 文案微调）；备选室内旗保留、庭院加第二
   触发点（任一通关）。
4. **map2 尺寸/骨架**：默认 140×84 + 三横一纵街网 + 北侧可进入建筑 ×3 + 南侧装饰带 +
   东北信标土丘（§4.1）；希望调整（如更大广场、河道穿城）请指示。
5. **结算口径**：默认每关独立（击杀/命中率/拾取/用时）+ 最终关加全程累计行；命中率按
   "击发次数"计（霰弹一发=一次）。
