## 一、目标

室内建筑（map0 城区仓库区）的二楼、三楼成为**可玩层**：玩家能从一楼经坡道走上二层、三层，
楼上可战斗、可拾取、可被小地图正确呈现；敌人不隔层误侦测。里程碑判据：

- **A-M1（批 3）**：玩家从一楼走坡道登上东侧仓库上方二层夹层，楼上有敌人/拾取物/战斗。
- **A-M2（批 4）**：三层退台可玩贯通（二层 → 三层坡道连通），建筑体量与既有 7.8m 装饰外立面视觉自洽。
- **A-M3（批 5）**：小地图楼层化——按玩家所在楼层切换墙集渲染。

## 二、现状与约束（代码勘察结论）

| 系统 | 现状 | 多层影响 |
| --- | --- | --- |
| 数据 | `LevelData.MAPS` 单层符号图（自动生成禁手改）；`level_ext.json` 已有 terrain 段（P2b 第一批平台+斜坡） | 需 layers 扩展层，走 level_ext 配置层（红线合规） |
| 几何 | 墙 = 全高 2.6m BoxMultiMesh（y∈[0,2.6]）；地板/天花板整片 PlaneMesh；`_build_terrain` 已有通用平台/坡板工厂（BoxMesh+BoxShape 同源、正交 Basis 坡面、≥45° 容错） | 楼板 = 逐格板 + 挖洞；多层墙按层 y 偏移；坡道加"所在层底高"参数即可复用 |
| 碰撞 | 每墙格 BoxShape（挂 `WallCollision`，计数==墙格数 4197，SmokeTest 断言守护）；地面 WorldBoundaryShape 无限平面 | 楼板/层墙需追加碰撞体；**不变式需按层扩展**（见 5.4） |
| 玩家 | CharacterBody3D + 重力 + move_and_slide，无跳跃键，≤45° 坡天然可行走（P2b 已实证高差 1.30m 登顶） | 零改动 |
| 敌人 | 侦测/攻击距离为**水平投影完全忽略 y**（`Enemy.gd` `to_player.y = 0`）；有重力+move_and_slide（贴地天然成立）；直线追击无寻路 | 批 2 前置改造：垂直差阈值；隔层开火随侦测一并解决 |
| 子弹 | 3D 物理飞行，命中静态体即止 | 楼板有碰撞即天然遮挡，零改动 |
| 小地图 | `wall_cells`（Vector2i 字典，**纯 2D 无层概念**）预渲染单层纹理 | 引入"当前楼层"，按层取墙集 |
| 天花板 | 整片 y=2.6 覆盖原地图矩形（庭院在矩形外自然露天） | 二/三层区天花板需分层抬升（三层顶 7.8m 与外立面同高） |

**已知硬坑**（本线全程适用，实证记录见 STATUS 交接须知）：

1. **读图偏移坑**：`LevelData.MAPS[n]` 三引号串以换行开头，`split("\n")` 后 `rows[0]` 为空行——
   level_ext 一切坐标（贴花/道具/地形/**layers 格**）落位必须按**符号 row**（`rows[y+1]`）对照
   `wall_cells`/地板格核验，禁止按源码行号填写（大门贴花悬浮事故根因，已热修）。
2. 导入缓存坑（改贴图先 `--headless --import`）、暂停体系（实体挂 Viewport 子树）、
   测试挂 `_physics_process` 等照旧。

## 三、层叠数据模型（layers 段设计）

### 3.1 配置 schema（`level_ext.json` 新增 `layers` 数组）

```json
"layers": [
  {
    "map": 0, "floor": 2,
    "baseHeight": 2.6,
    "rect": { "x": 150, "y": 26, "w": 18, "h": 13 },
    "grid": ["XXXXX...", "X     X", "..."],
    "slabHoles": [ { "x": 155, "y": 30 }, { "x": 156, "y": 30 } ],
    "enemies": [ { "x": 160, "y": 30, "id": 1 } ],
    "pickups": [ { "x": 158, "y": 28, "symbol": "H" } ]
  },
  {
    "map": 0, "floor": 3,
    "baseHeight": 5.2,
    "rect": { "x": 152, "y": 28, "w": 12, "h": 9 },
    "grid": ["..."],
    "slabHoles": []
  }
]
```

字段语义：

- **floor**：楼层序号（2=二层，3=三层）；**baseHeight**：该层地板（楼板）顶面高度 = (floor-1)×2.6m。
- **rect**：该层覆盖的矩形格区（**绝对地图坐标**，与 level_ext 其他段一致）。
- **grid**：该层独立符号网格（**相对 rect 原点的紧凑行数组**，行 = 符号 row）。沿用现有符号语义：
  `X/M/S/G`=墙、`0/1/2`=敌人、`H/C/A/e/h`=拾取；空格 = 该层无物（露出下层楼板或挖空）。
  **上层网格为下层足迹的子集**（自然退台，用户既定要求）——生成时校验：上层墙/实体格必须落在
  下层墙格或下层楼板覆盖范围内，越界格告警跳过。
- **slabHoles**：楼板挖洞格（**绝对坐标**），用于挑空/楼梯井/坡道穿板——坡道从一层上二层必须
  在二层楼板对应位置开洞。**注意坐标基准**：grid 相对、slabHoles 绝对，混用易错，文档与实现
  注释双向标注。
- **enemies/pickups**：二层实体布置（绝对坐标）。不进 grid 是因为 grid 保持"结构层"纯粹性，
  实体布置与既有 weaponPickups/shellSpawns 等"绝对坐标配置"风格一致。

### 3.2 生成逻辑（`LevelGenerator` 新增 `_build_layers(map_index)`）

构建顺序插在 `_build_terrain` 之后：

1. **楼板**：逐格 BoxMesh 板（厚 0.3m，顶面 = baseHeight）+ 逐格 BoxShape 碰撞，slabHoles 格跳过。
   逐格而非整片 PlaneMesh：挖洞天然、与墙体接缝干净；量级可控（二层试点 ~200 格）。
   不做 MultiMesh 合并优化（首期），实机若卡顿再条带合并（2026-08-26 规划预留方案）。
2. **层墙**：复用 `_build_walls` 的 MultiMesh 模式，按 grid 逐格生成，y 偏移 baseHeight，
   墙高仍 2.6m（二层顶 = 5.2 = 三层底，对齐）。材质按符号沿用 WALL_TEXTURES。
3. **层天花板**：三层区（最高层）上方 y = 顶高（7.8m，与装饰外立面总高一致，视觉自洽）
   逐格板覆盖最高层 rect；二层独立区（无三层覆盖处）天花板 @ 5.2m。复用楼板生成器
   （"顶板"=楼板挖洞集为空的特例）。
4. **实体**：enemies/pickups 按 baseHeight 抬升生成（敌人 y=baseHeight 落地由重力保证）。
5. **登记**：层墙**不进一楼 `wall_cells`**，进新成员 `_layer_cells: Dictionary`
   （`floor(int) -> Dictionary(Vector2i->符号)`）；`is_wall(x, y, floor := 1)` 加默认参数，
   存量调用（AI/拾取落位/测试）零改动。`get_layer_cells(floor)` 访问器供小地图/测试消费。

### 3.3 向后兼容（红线）

- 无 `layers` 配置或 `map` 不匹配 → `_build_layers` 直接 return，行为与现状完全一致。
- 一楼 `wall_cells`/`WallCollision` 计数不变式**保持原样**（4197==4197 断言不动），
  层墙/楼板碰撞挂独立 body（`Terrain_*` 同模式，命名 `Layer_Floor2` / `LayerWall_2_X` 等，
  挂 `terrain`/`layers` 组）。SmokeTest 存量 109 项零破坏，新断言只追加。

## 四、敌人 y 感知 / 地面吸附（前置批，本线批 2）

### 4.1 问题清单与方案

| 问题 | 方案 |
| --- | --- |
| 隔层误侦测（楼下敌锁定楼上玩家） | 侦测判定加**垂直差阈值**：`abs(to_player.y) > detectionVerticalTolerance` 时不侦测不追击不攻击。阈值进 `enemies.json`（默认 1.5m ≈ 0.6×层高），配置驱动 |
| 对楼板开火 | 随侦测一并解决（不侦测即不开火）；攻击弹道本身 3D，无需改 |
| 敌人不会走坡道 | 直线追击 + move_and_slide 天然可上 ≤45° 坡（与玩家同机制）——**验证为主，无代码**。实测若卡坡侧（胶囊边缘），兜底：贴坡格速度衰减 |
| 悬空不落地 | 敌人本有重力+move_and_slide，天然落地。二层 spawn 位置 y=baseHeight 由 layers 生成保证（批 3）；批 2 用庭院平台验证 |
| 平地假设残留 | 攻击判定距离仍为水平投影（保持），仅**侦测门槛**加 y 过滤——改动最小、行为可预期 |

首期设计约束兜底（2026-08-26 规划既定）：**二层少刷/不刷敌**（试点夹层刷 1-2 个固定哨戒敌），
完整层感知寻路不在本阶段范围。

### 4.2 批 2 改动面

- `Enemy.gd`：`_physics_process` 侦测分支加 y 差阈值（约 +6 行）。
- `enemies.json`：模板加 `detectionVerticalTolerance` 字段。
- `SmokeTest.gd`：+4 断言——①敌人配置含垂直阈值；②庭院平台上玩家不被地面敌人侦测
  （敌 `velocity` 保持零/不进入攻击冷却）；③敌人沿坡道追击可上升（坡底放敌、平台顶玩家，
  N 物理帧后敌 y 上升）；④地面敌人侦测平地玩家行为不变（回归保护）。

## 五、坡道/楼梯进室内 + 三楼

### 5.1 垂直通行一律坡道化（既定约束）

玩家无跳跃键，台阶式楼梯直接爬不上——**所有层间通行 = 坡道**（视觉可做"楼梯状坡道"：
坡面贴图切台阶纹理，物理仍为 ≤45° 斜面；贴图属美术项，走 AI 生成稿过用户流程）。

### 5.2 复用 P2b 地形工厂

`_build_terrain` 的 platform/ramp 加 `floor`（默认 1）字段：`baseHeight = (floor-1)×2.6`，
即平台/坡道的 y 基准从"地面 0"改为"所在层地板顶面"。生成代码改动集中在
`_build_terrain_platform/_build_terrain_ramp` 取基面高度一处，其余（正交 Basis 坡面、
碰撞、防缝 overlap）零改动。一层既有配置（庭院土丘）不带 floor 字段 → 默认 1，向后兼容。

### 5.3 坡道穿板

一层→二层坡道穿过二层楼板处：对应格加入该层 `slabHoles`。坡道顶端高 = baseHeight，
与二层楼板顶面精确衔接（P2b 已验证 1.30m 登顶精度 <5cm，层高 2.6m 同机制放大）。
**坡道坡度约束**：层高 2.6m、≤45° → 最短水平跨距 2.6m = 1.3 格 → 实际取 ≥2 格（4m，
坡度 33°）保行走顺滑；试点用 3 格缓坡（12.2° 同庭院）。

### 5.4 三楼（批 4）

- rect 为二层 rect 子集（退台）；墙/楼板/实体同二层机制。
- 三层顶板 @ 7.8m —— 与既有装饰外立面总高（7.8m 三层体量）**精确对齐**，出门回头视线里
  真实三层结构与立面布景无缝衔接（本设计的高光点）。
- 二层→三层坡道走退台露台段（局部露天，与庭院夜空衔接）。

## 六、小地图楼层化（批 5）

- `MiniMap.setup` 改为收集多层墙集：一楼 `wall_cells` + `_layer_cells[2..n]`，各自预渲染
  ImageTexture（一图一层）。
- 运行时**当前楼层判定**：玩家 y 落在 `[层底+0.3, 下一层底-0.3]` 区间判定所在层（0.3m 缓冲
  防坡道穿越瞬间抖动）；楼层判定配置由 layers baseHeight 派生，硬编码零。
- 切层时 `queue_redraw` 换纹理；跟随模式视窗逻辑不变。楼层标识（"F1/F2/F3" 小字）加在
  小地图角落，贴图/字体沿用 HUD 现有风格。
- 敌人红点/信标绿点同层过滤（`_layer_cells` 对应层的实体才画）。

## 十、决策点（请用户拍板）

1. **二层夹层选址**：默认东侧仓库上方（2026-08-26 规划草图 rect col150-167/row26-38 内取
   ~18×13 子区，实施前按 wall_cells BFS 核验，遵守读图偏移坑）。如希望换位置（如北部仓库上方）
   请指示。
2. **二层敌人密度**：默认试点刷 1-2 个固定哨戒敌（不巡弋）；如要"零敌纯探索"也可，请指示。
3. **楼梯状坡道贴图**：批 4 美术项，AI 生成稿会先过目再入库（既定流程）；如想沿用纯坡面
   （不做楼梯纹理）可省一项美术。
4. **三楼露台**（退台处局部露天，夜空可见）：默认做，如要全封闭三层请指示。
